## ۱. چشم‌انداز کلی سیستم

### هدف اصلی
این سرویس یک **سیستم پیشنهاد دوره هوشمند** برای پلتفرم آموزشی است. کار این سرویس این است که:

> **برای هر دانشجو، دوره‌هایی را پیشنهاد دهد که بیشترین تناسب را با نقاط ضعف، سطح یادگیری و علایق قبلی او دارند.**

### مثال ساده
فرض کنید یک دانشجو:
- دوره‌های «برنامه‌نویسی پایتون» و «تحلیل داده» را گذرانده (سطح متوسط)
- در آزمون‌ها در مهارت «SQL» ضعیف عمل کرده (کمتر از ۵۰٪)
- علاقه‌اش به دسته‌بندی «برنامه‌نویسی» است

سیستم به او دوره «پیشرفته SQL» را با امتیاز بالا پیشنهاد می‌دهد و با هوش مصنوعی یک جمله توضیحی فارسی هم می‌نویسد.

## ۲. ساختار داده‌ها

### `CourseCandidate` — دوره‌های کاندید
این اینترفیس نشان می‌دهد هر دوره‌ای که به عنوان گزینه پیشنهاد بررسی می‌شود چه ویژگی‌هایی دارد:

```typescript
interface CourseCandidate {
  courseId: number;         // شناسه یکتای دوره
  title: string;           // عنوان دوره
  categoryId: number;      // شناسه دسته‌بندی (برای مقایسه)
  categoryTitle: string;   // عنوان دسته‌بندی
  levelName: string | null;// سطح دوره (مقدماتی/متوسط/پیشرفته)
  averageRating: number;   // میانگین امتیاز نظرات
  skillTags: string[];     // تگ‌های مهارتی استخراج شده از سوالات آزمون
  thumbnail: string | null;// تصویر کوچک دوره
}
```

**نکته مهم:** تگ‌های مهارتی (`skillTags`) از سوالات آزمون‌های دوره استخراج می‌شوند. یعنی اگر آزمون‌های یک دوره شامل سوالاتی با تگ «React» باشند، آن دوره مهارت «React» را پوشش می‌دهد.

---

### `ScoredCourse` — دوره‌ها با امتیاز
وقتی یک دوره کاندید امتیاز می‌گیرد:

```typescript
interface ScoredCourse extends CourseCandidate {
  score: number;             // امتیاز نرمالایز شده ۰ تا ۱۰۰
  matchedSkillTags: string[];// تگ‌های ضعیف دانشجو که این دوره پوشش می‌دهد
  reason?: string;           // توضیح فارسی تولید شده توسط هوش مصنوعی
}
```

---

### `StudentProfile` — پروفایل دانشجو
پروفایل هر دانشجو شامل ۴ بخش است:

```typescript
interface StudentProfile {
  completedCourseIds: number[];   // دوره‌های تکمیل‌شده
  weakSkills: SkillStat[];       // مهارت‌های ضعیف (زیر ۵۰٪)
  avgCompletedLevel: number | null;// میانگین سطح دوره‌های قبلی (۱-۳)
  favoriteCategoryIds: number[];  // دسته‌بندی‌های دوره‌های قبلی
}
```

## ۴. هسته الگوریتم — تابع امتیازدهی خالص

### `scoreCourse()` — تابع محاسبه امتیاز

> **نکته آکادمیک:** این تابع یک **pure function** است، یعنی بدون نیاز به دیتابیس کار می‌کند و فقط با دریافت ورودی، خروجی تولید می‌کند. این ویژگی باعث می‌شود تست‌پذیری بسیار بالا برود.

### فرمول امتیازدهی:

```
امتیاز کل = (Skill_Gap × ۰.۴۵) + (Level × ۰.۲۵) + (Category × ۰.۲) + (Quality × ۰.۱)
```

#### ۱. **پوشش نقاط ضعف (Skill Gap Match) — وزن ۴۵٪**

**مفهوم:** آیا این دوره مهارت‌هایی را پوشش می‌دهد که دانشجو در آن‌ها ضعیف است؟

**روش محاسبه:**
1. مهارت‌های ضعیف دانشجو (زیر ۵۰٪) در یک `Set` ریخته می‌شوند
2. مهارت‌های دوره (از تگ‌های سوالات آزمون) در `Set` دیگری ریخته می‌شوند
3. تعداد مهارت‌های مشترک شمرده می‌شود
4. نسبت مشترک‌ها به کل مهارت‌های ضعیف، امتیاز را تعیین می‌کند

```
مثال:
- مهارت‌های ضعیف دانشجو: ["SQL", "React", "Docker"]
- مهارت‌های دوره: ["React", "TypeScript", "Node.js"]
- مشترک‌ها: ["React"] → ۱ از ۳ = ۳۳٪
- امتیاز: ۳۳ × ۰.۴۵ = ۱۴.۸۵ از ۴۵
```

**چرا ۴۵٪؟** چون مهم‌ترین هدف سیستم، رفع نقاط ضعف دانشجو است. اگر یک دوره دقیقاً مهارت‌های ضعیف او را پوشش دهد، بالاترین امتیاز را می‌گیرد.

---

#### ۲. **همراستایی سطح (Level Progression) — وزن ۲۵٪**

**مفهوم:** آیا سطح دوره پیشنهادی با سطح فعلی دانشجو هم‌خوانی دارد؟

**روش محاسبه:**
1. سطح دوره‌های تکمیل‌شده دانشجو میانگین گرفته می‌شود (مقدماتی=۱، متوسط=۲، پیشرفته=۳)
2. سطح ایده‌آل = میانگین + ۱ (یک پله بالاتر)
3. با استفاده از تابع نمایی `exp()`، هرچه فاصله سطح دوره با سطح ایده‌آل کمتر باشد، امتیاز بیشتر است

```
مثال:
- میانگین سطح دوره‌های قبلی: ۱.۵ (بین مقدماتی و متوسط)
- سطح ایده‌آل: ۲.۵
- دوره «متوسط» (سطح ۲): فاصله = ۰.۵ → امتیاز بالا
- دوره «پیشرفته» (سطح ۳): فاصله = ۰.۵ → امتیاز بالا
- دوره «مقدماتی» (سطح ۱): فاصله = ۱.۵ → امتیاز پایین‌تر
```

**چرا ۲۵٪؟** پیشرفت تدریجی در یادگیری اهمیت زیادی دارد. دوره خیلی ساده برای دانشجو کسل‌کننده و خیلی سخت برای او ناامیدکننده است.

---

#### ۳. **علایق دسته‌بندی (Category Affinity) — وزن ۲۰٪**

**مفهوم:** آیا دسته‌بندی این دوره با حوزه‌های قبلی دانشجو یکسان است؟

**روش محاسبه:**
- اگر دسته‌بندی دوره در لیست دسته‌بندی‌های دوره‌های قبلی دانشجو باشد → امتیاز کامل (۱۰۰)
- در غیر این صورت → صفر

```
مثال:
- دانشجو دوره‌هایی از دسته «برنامه‌نویسی» گذرانده
- دوره پیشنهادی: «طراحی وب» (دسته «برنامه‌نویسی») → امتیاز کامل
- دوره پیشنهادی: «بازاریابی دیجیتال» (دسته «بازاریابی») → امتیاز صفر
```

**چرا ۲۰٪؟** دانشجویان معمولاً در یک حوزه تخصصی علاقه‌مند هستند و اگر در دوره‌های برنامه‌نویسی شرکت کرده باشند، احتمالاً به دوره‌های برنامه‌نویسی دیگری هم علاقه دارند.

---

#### ۴. **کیفیت دوره (Course Quality) — وزن ۱۰٪**

**مفهوم:** آیا این دوره از نظر نظرات دانشجویان قبلی باکیفیت است؟

**روش محاسبه:**
- امتیاز میانگین دوره (۰ تا ۵) به مقیاس ۰ تا ۱۰۰ نرمالایز می‌شود

```
مثال:
- دوره با امتیاز ۴.۵ از ۵ → امتیاز: ۹۰
- امتیاز نهایی از این مؤلفه: ۹۰ × ۰.۱ = ۹ از ۱۰
```

**چرا ۱۰٪؟** کیفیت دوره مهم است اما اولویت اول، رفع نقاط ضعف دانشجو است، نه صرفاً دوره‌های محبوب.

---

### جدول خلاصه وزن‌ها

| مؤلفه | وزن | توضیح |
|-------|------|-------|
| **Skill Gap Match** | ۴۵٪ | پوشش مهارت‌های ضعیف دانشجو |
| **Level Progression** | ۲۵٪ | همراستایی سطح با پیشرفت تدریجی |
| **Category Affinity** | ۲۰٪ | تطابق با دسته‌بندی‌های قبلی |
| **Course Quality** | ۱۰٪ | امتیاز نظرات سایر دانشجویان |

## ۵. لایه پایگاه داده

### `buildStudentProfile()` — ساخت پروفایل دانشجو

این متد پروفایل ۴ بخشی دانشجو را می‌سازد:

```
۱. گواهینامه‌ها → دوره‌های تکمیل‌شده
   └── SELECT * FROM certificates WHERE Student_Id = ?
       └── Include: Courses → CategoryId, Level.LevelName

۲. میانگین سطح → محاسبه عددی
   └── مقدماتی=۱، متوسط=۲، پیشرفته=۳
   └── average = sum(levels) / count(levels)

۳. دسته‌بندی‌های محبوب → لیست یونیک
   └── SET of CategoryId ها از دوره‌های قبلی

۴. مهارت‌های ضعیف → از AnalyticsService
   └── getMySkillProfile(studentId)
   └── فیلتر: percentage < 50
```

---

### `getCandidateCourses()` — دریافت دوره‌های کاندید

این متد لیست دوره‌هایی را برمی‌گرداند که:
1. **منتشر شده باشند** (`IsPublished = true`)
2. **دانشجو در آن‌ها ثبت‌نام نکرده باشد**

```
کوئری اصلی:
SELECT * FROM courses
WHERE IsPublished = true
  AND Id NOT IN ( enrolled_courses ∪ completed_courses )
INCLUDE:
  - Category.Title
  - Level.LevelName
  - Quizzes → QuizQuestions.SkillTag
```

**نکته مهم:** تگ‌های مهارتی هر دوره از سوالات آزمون‌های آن دوره استخراج می‌شوند. این یعنی:
- اگر آزمون‌های یک دوره شامل سوالاتی با تگ «Python» باشند
- آن دوره مهارت «Python» را آموزش می‌دهد
- پس اگر دانشجو در «Python» ضعیف باشد، این دوره برایش مفید است

## ۶. یکپارچه‌سازی هوش مصنوعی (LLM)

### `generateReason()` — تولید توضیح فارسی

این متد از یک **مدل زبانی کوچک (Qwen-3 4B)** برای تولید جملات توضیحی فارسی استفاده می‌کند.

**چرا از هوش مصنوعی استفاده می‌شود؟**
- توضیحات تولید شده طبیعی‌تر و شخصی‌سازی شده‌تر هستند
- دانشجو احساس می‌کند سیستم واقعاً شرایط او را درک می‌کند

**روش کار:**
```
۱. بررسی وجود تگ‌های مشترک
   ├── اگر تگ مشترکی نباشد → پیام عمومی
   └── اگر تگ مشترک باشد → ادامه به LLM

۲. ارسال درخواست به LLM
   ├── System Prompt: تو یک مشاور آموزشی هستی...
   ├── User Prompt: دانشجو در مهارت X ضعیف است...
   └── Parameters: temperature=0.7, max_tokens=100

۳. بررسی پاسخ
   ├── اگر معتبر بود → استفاده از پاسخ LLM
   └── اگر نامعتبر یا خطا → استفاده از fallback قالبی
```

**مثال‌ها:**

| وضعیت | خروجی |
|-------|-------|
| تگ مشترک وجود دارد | `این دوره مهارت SQL را تقویت می‌کند` (تولید شده توسط LLM) |
| تگ مشترک وجود ندارد | `این دوره با سطح و زمینه یادگیری شما هم‌راستا است` |
| LLM در دسترس نیست | `این دوره روی مهارت‌های React، Docker تمرکز دارد` |

**معماری Fallback:**
```
LLM موفق؟ ──آره──→ پاسخ LLM
    │
    نه
    │
    ▼
پاسخ قالبی (Fallback)
```

## ۷. متدهای API عمومی

### ۱. `getRecommendations()` — دریافت پیشنهادها

**ورودی:** شناسه دانشجو + کاربر فعلی  
**خروجی:** لیست دوره‌های پیشنهادی با امتیاز و توضیح

```
جریان اجرا:
۱. بررسی مجوز (مالکیت یا ادمین)
۲. بررسی کش موجود
   ├── کش معتبر (زیر ۲۴ ساعت) → بازگشت از کش
   └── کش قدیمی یا وجود ندارد → ادامه
۳. محاسبه جدید → فراخوانی refresh()
۴. بازخوانی از دیتابیس → بازگشت نتیجه
```

---

### ۲. `refresh()` — محاسبه مجدد پیشنهادها

**ورودی:** شناسه دانشجو + تعداد دوره‌های پیشنهادی (پیش‌فرض ۵)  
**خروجی:** void (نتایج در دیتابیس ذخیره می‌شوند)

```
جریان اجرا:
۱. ساخت پروفایل دانشجو ← buildStudentProfile()
۲. دریافت دوره‌های کاندید ← getCandidateCourses()
۳. امتیازدهی به همه کاندیدها ← scoreCourse() برای هرکدام
۴. مرتب‌سازی نزولی بر اساس امتیاز
۵. انتخاب N دوره برتر
۶. تولید توضیح فارسی با LLM ← generateReason() برای هرکدام
۷. حذف پیشنهادهای قدیمی برای همان دوره‌ها
۸. ذخیره پیشنهادهای جدید در دیتابیس
```

---

### ۳. `dismiss()` — علاقه‌مند نیستم

**ورودی:** شناسه پیشنهاد + کاربر فعلی  
**خروجی:** void

```
تغییر وضعیت از Active → Dismissed
```

**کاربرد:** وقتی دانشجو به دوره‌ای علاقه ندارد، آن را از لیست فعال حذف می‌کند.

---

### ۴. `getHistory()` — تاریخچه و نرخ تبدیل

**ورودی:** شناسه دانشجو + کاربر فعلی  
**خروجی:** لیست کامل پیشنهادها + آمار

```
خروجی شامل:
{
  history: [
    { id, courseId, courseTitle, score, reason, status, generatedAt }
  ],
  stats: {
    total: تعداد کل پیشنهادها,
    enrolled: تعداد ثبت‌نام شده,
    dismissed: تعداد رد شده,
    active: تعداد فعال,
    conversionRate: درصد نرخ تبدیل
  }
}
```

**نرخ تبدیل** = (تعداد ثبت‌نام / تعداد کل) × ۱۰۰

---

### ۵. `markAsEnrolled()` — به‌روزرسانی وضعیت

**ورودی:** شناسه دانشجو + شناسه دوره  
**خروجی:** void

```
وقتی دانشجو در دوره‌ای ثبت‌نام می‌کند:
وضعیت پیشنهاد مربوطه Active → Enrolled تغییر می‌کند
```

## ۱۰. نکات مهم برای دفاع

### ✅ نقاط قوت طراحی

1. **Separation of Concerns:** هر بخش مسئولیت مشخصی دارد
   - Profile Builder → ساخت پروفایل
   - Candidate Fetcher → دریافت گزینه‌ها
   - Scoring Engine → امتیازدهی
   - LLM Explainer → تولید توضیح

2. **Pure Functions:** تابع `scoreCourse()` بدون وابستگی به دیتابیس است و قابل تست خالص است

3. **Caching Strategy:** استفاده از کش ۲۴ ساعته برای کاهش بار پردازش

4. **Fallback Pattern:** اگر هوش مصنوعی در دسترس نباشد، سیستم با پیام‌های قالبی کار می‌کند

5. **Configurable Weights:** وزن‌های الگوریتم در یک مکان مشخص و قابل تنظیم هستند

6. **Status Tracking:** وضعیت پیشنهادها قابل پیگیری است (Active → Enrolled/Dismissed)

### ❌ محدودیت‌ها و بهبودهای احتمالی

1. **عدم استفاده از Collaborative Filtering:** فقط از محتوا-محور (Content-Based) استفاده شده، نه از همکاران (Collaborative)

2. **عدم در نظر گرفتن زمان دوره‌ها:** مدت دوره در امتیازدهی لحاظ نشده

3. **عدم در نظر گرفتن هزینه دوره:** قیمت دوره در امتیازدهی نقشی ندارد

4. **کش ساده:** فقط بر اساس زمان، نه بر اساس تغییرات دیتابیس

### 💡 پیشنهادات برای ارتقاء

1. افزودن **Collaborative Filtering** (دوره‌هایی که دانشجویان مشابه گذرانده‌اند)
2. افزودن **A/B Testing** برای مقایسه عملکرد الگوریتم
3. استفاده از **Redis** برای کش به جای دیتابیس
4. افزودن **فیلتر قیمت** (دوره‌های متناسب با بودجه دانشجو)
5. افزودن **溱болentine deduplication** (جلوگیری از پیشنهاد دوره‌های تقریباً مشابه)
