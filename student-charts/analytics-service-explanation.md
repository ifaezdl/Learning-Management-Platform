## ۱. چشم‌انداز کلی سیستم

### هدف اصلی
این سرویس یک **سیستم تحلیل و هوشمندسازی یادگیری** برای پلتفرم آموزشی است. کار این سرویس این است که:

> **نمرات آزمون‌ها و پیشرفت یادگیری دانشجویان را تحلیل کند، نقاط ضعف آن‌ها را شناسایی کند و روند یادگیری‌شان را پیگیری نماید.**

### مثال ساده
فرض کنید یک دانشجو ۳ آزمون داده:
- آزمون ۱: نمره ۶۰٪ (مهارت React: ۸۰٪، SQL: ۴۰٪)
- آزمون ۲: نمره ۷۰٪ (مهارت React: ۸۵٪، SQL: ۵۵٪)
- آزمون ۳: نمره ۸۵٪ (مهارت React: ۹۰٪، SQL: ۷۰٪)

سیستم می‌تواند:
- بگوید «SQL مهارت ضعیف دانشجو است»
- نشان دهد «روند یادگیری صعودی است»
- به مدرس بگوید «نمره کلاس در SQL پایین است»

## ۲. ساختار داده‌ها

### `SkillStat` — آمار یک مهارت
```typescript
interface SkillStat {
  tag: string;       // نام مهارت (مثلاً: "React", "SQL", "Docker")
  correct: number;   // تعداد پاسخ‌های صحیح
  total: number;     // تعداد کل سوالات
  percentage: number;// درصد صحیح (۰ تا ۱۰۰)
}
```

### `SkillBreakdownResult` — نتیجه تحلیل یک آزمون
```typescript
interface SkillBreakdownResult {
  attemptId: number;      // شناسه آزمون
  skills: SkillStat[];    // لیست مهارت‌ها با درصد
}
```

### `QuizScorePoint` — نقطه نمره آزمون
```typescript
interface QuizScorePoint {
  date: Date;             // تاریخ آزمون
  percentage: number;     // درصد نمره
  courseTitle: string;    // عنوان دوره
}
```

### `CompletionPoint` — نقطه پیشرفت دوره
```typescript
interface CompletionPoint {
  date: Date;             // تاریخ تکمیل درس
  percentage: number;     // درصد پیشرفت دوره
  courseTitle: string;    // عنوان دوره
}
```

### `ProgressTrendResult` — نتیجه روند پیشرفت
```typescript
interface ProgressTrendResult {
  quizScores: QuizScorePoint[];          // سری نمرات آزمون‌ها
  courseCompletion: CompletionPoint[];    // سری پیشرفت دوره‌ها
}
```

### `TrendClassification` — دسته‌بندی روند
```typescript
interface TrendClassification {
  status: 'صعودی' | 'نزولی' | 'ثابت' | 'داده کافی نیست';
  slope: number;       // شیب خط رگرسیون
  description?: string;// توضیح فارسی
}
```

## ۳. تابع `groupBySkill` — گروه‌بندی بر اساس مهارت

> **نکته آکادمیک:** این تابع یک **pure function** است و بدون وابستگی به دیتابیس کار می‌کند.

### هدف
تبدیل لیست پاسخ‌های آزمون به آمار هر مهارت.

### ورودی
```typescript
answers: { skillTag: string | null; isCorrect: boolean }[]
```
مثال:
```json
[
  { "skillTag": "React", "isCorrect": true },
  { "skillTag": "React", "isCorrect": false },
  { "skillTag": "SQL",   "isCorrect": false },
  { "skillTag": null,     "isCorrect": true }
]
```

### الگوریتم
```
۱. ایجاد Map برای هر skillTag
   └── هر تگ → { correct: 0, total: 0 }

۲. بررسی هر پاسخ
   ├── اگر skillTag خالی بود → "سایر"
   └── افزایش total
       └── اگر isCorrect = true → افزایش correct

۳. محاسبه درصد هر مهارت
   └── percentage = round((correct / total) × 100)

۴. مرتب‌سازی صعودی (ضعیف‌ترین اول)
```

### خروجی
```json
[
  { "tag": "SQL",    "correct": 0, "total": 1, "percentage": 0 },
  { "tag": "React",  "correct": 1, "total": 2, "percentage": 50 },
  { "tag": "سایر",   "correct": 1, "total": 1, "percentage": 100 }
]
```

**نکته:** مرتب‌سازی صعودی است، یعنی ضعیف‌ترین مهارت‌ها اول می‌آیند. این ویژگی برای سرویس پیشنهاد دوره بسیار مفید است.

## ۴. تابع `classifyTrend` — تشخیص روند یادگیری

> **نکته آکادمیک:** این تابع از **رگرسیون خطی (Least Squares)** برای تشخیص روند استفاده می‌کند.

### هدف
تشخیص اینکه نمرات دانشجو در طول زمان **صعودی**، **نزولی** یا **ثابت** بوده است.

### ورودی
```typescript
scores: { date: Date; percentage: number }[]
```

### الگوریتم رگرسیون خطی

```
مرحله ۱: بررسی شرایط اولیه
├── اگر کمتر از ۲ نقطه باشد → "داده کافی نیست"
└── اگر همه نمرات یکسان باشند → "ثابت"

مرحله ۲: مرتب‌سازی بر اساس تاریخ (صعودی)

مرحله ۳: محاسبه پارامترهای رگرسیون
├── x = شماره آزمون (0, 1, 2, ...)
├── y = درصد نمره
├── sumX = Σx
├── sumY = Σy
├── sumXY = Σ(x × y)
└── sumX2 = Σ(x²)

مرحله ۴: محاسبه شیب (slope)
slope = (n × sumXY - sumX × sumY) / (n × sumX2 - sumX²)

مرحله ۵: دسته‌بندی بر اساس شیب
├── slope > +2 → "صعودی"
├── slope < -2 → "نزولی"
└── -2 ≤ slope ≤ +2 → "ثابت"
```

### مثال عددی کامل

فرض کنید دانشجو ۴ آزمون داده:
| آزمون | تاریخ | نمره (٪) |
|-------|--------|----------|
| ۱ | فروردین | ۵۰ |
| ۲ | اردیبهشت | ۶۰ |
| ۳ | خرداد | ۷۰ |
| ۴ | تیر | ۸۰ |

```
محاسبه:
n = 4
x = [0, 1, 2, 3]
y = [50, 60, 70, 80]

sumX = 0+1+2+3 = 6
sumY = 50+60+70+80 = 260
sumXY = (0×50)+(1×60)+(2×70)+(3×80) = 0+60+140+240 = 440
sumX2 = 0+1+4+9 = 14

slope = (4×440 - 6×260) / (4×14 - 6²)
      = (1760 - 1560) / (56 - 36)
      = 200 / 20
      = 10

نتیجه: slope = 10 > 2 → "صعودی" ✅
```

### نمودار بصری
```
نمره
۱۰۰│
 ۹۰│
 ۸۰│                        ●
 ۷۰│                  ●
 ۶۰│            ●
 ۵۰│      ●
 ۴۰│
 ۳۰│
    └──────────────────────────
      آ۱   آ۲   آ۳   آ۴   زمان

    شیب مثبت → روند صعودی 📈
```

## ۵. Endpoint ۱ — تحلیل مهارتی یک آزمون

### `getAttemptSkills()`

**هدف:** نمایش درصد هر مهارت در یک آزمون خاص

**ورودی:** شناسه آزمون + کاربر فعلی

**جریان اجرا:**
```
۱. دریافت اطلاعات آزمون از دیتابیس
   └── QuizAttempt → Quizzes → Courses → Teacher_Id

۲. بررسی دسترسی
   ├── مالک آزمون؟ (دانشجوی خودش)
   ├── مدرس دوره؟ (مدرس دوره مربوطه)
   └── ادمین؟

۳. دریافت پاسخ‌های آزمون
   └── QuizAttemptAnswers → QuizQuestions.SkillTag

۴. تبدیل به فرمت مناسب
   └── { skillTag, isCorrect }

۵. فراخوانی groupBySkill()
   └── بازگشت نتیجه
```

**خروجی:**
```json
{
  "attemptId": 123,
  "skills": [
    { "tag": "SQL", "correct": 2, "total": 5, "percentage": 40 },
    { "tag": "React", "correct": 4, "total": 5, "percentage": 80 },
    { "tag": "Docker", "correct": 3, "total": 5, "percentage": 60 }
  ]
}
```

## ۶. Endpoint ۲ — پروفایل مهارتی کلی دانشجو

### `getMySkillProfile()`

**هدف:** نمایش درصد هر مهارت در **تمام آزمون‌های** یک دانشجو

**ورودی:** شناسه دانشجو + (اختیاری) شناسه دوره

**جریان اجرا:**
```
۱. دریافت همه آزمون‌های ثبت‌شده دانشجو
   └── WHERE Student_Id = ? AND SubmittedAt IS NOT NULL

۲. (اختیاری) فیلتر بر اساس دوره خاص

۳. دریافت همه پاسخ‌های آن آزمون‌ها
   └── WHERE Attempt_Id IN (attemptIds)

۴. تبدیل به فرمت مناسب
   └── { skillTag, isCorrect }

۵. فراخوانی groupBySkill()
   └── بازگشت نتیجه
```

**کاربردها:**
- نمایش نقاط ضعف دانشجو در داشبورد
- استفاده توسط سرویس **Recommendations** برای پیشنهاد دوره

## ۷. Endpoint ۳ — روند پیشرفت در زمان

### `getProgressTrend()`

**هدف:** نمایش دو سری زمانی:
1. **نمرات آزمون‌ها** در طول زمان
2. **پیشرفت دوره‌ها** (درصد تکمیل) در طول زمان

**ورودی:** شناسه دانشجو + (اختیاری) شناسه دوره

### بخش اول: نمرات آزمون‌ها
```
۱. دریافت آزمون‌های ثبت‌شده مرتب بر اساس تاریخ
۲. محاسبه درصد هر آزمون
   └── percentage = round((Score / MaxScore) × 100)
۳. بازگشت آرایه QuizScorePoint[]
```

### بخش دوم: پیشرفت دوره‌ها
```
۱. دریافت ثبت‌نام‌های دانشجو
۲. دریافت تعداد کل دروس منتشرشده هر دوره
   └── GROUP BY Course_Id → count(Lessons)
۳. دریافت دروس تکمیل‌شده مرتب بر اساس تاریخ تکمیل
   └── WHERE IsCompleted = true
۴. محاسبه پیشرفت تجمعی (Rolling)
   └── percentage = min(100, round((completed / total) × 100))
```

**خروجی:**
```json
{
  "quizScores": [
    { "date": "2025-01-15", "percentage": 60, "courseTitle": "پایتون" },
    { "date": "2025-02-20", "percentage": 75, "courseTitle": "پایتون" },
    { "date": "2025-03-10", "percentage": 85, "courseTitle": "تحلیل داده" }
  ],
  "courseCompletion": [
    { "date": "2025-01-10", "percentage": 25, "courseTitle": "پایتون" },
    { "date": "2025-02-05", "percentage": 50, "courseTitle": "پایتون" },
    { "date": "2025-03-01", "percentage": 100, "courseTitle": "پایتون" }
  ]
}
```

**نمودار بصری:**
```
٪ پیشرفت
۱۰۰│                              ●─── پایتون
 ۸۰│                   ●
 ۶۰│          ●                              ●── تحلیل داده
 ۴۰│                              ●
 ۲۰│   ●
   ۰│
     └──────────────────────────────────────
      فروردین    اردیبهشت    خرداد    تیر    زمان
```

## ۸. Endpoint ۴ — نمای کلی مهارت‌های کلاس (مدرس)

### `getCourseSkillsOverview()`

**هدف:** نمایش درصد متوسط هر مهارت در **تمام دانشجویان** یک دوره

**ورودی:** شناسه دوره + کاربر فعلی (مدرس یا ادمین)

**جریان اجرا:**
```
۱. بررسی دسترسی (مالک دوره یا ادمین)
۲. دریافت همه آزمون‌های منتشرشده دوره
۳. دریافت همه آزمون‌های ثبت‌شده دانشجویان
۴. دریافت همه پاسخ‌ها
۵. ترکیب همه پاسخ‌ها
۶. فراخوانی groupBySkill()
```

**کاربرد برای مدرس:**
- «بیشترین ضعف دانشجویان کلاس در کدام مهارت است؟»
- «آیا نیاز به مرور مجدد موضوع X دارم؟»

## ۱۳. نکات مهم برای دفاع

### ✅ نقاط قوت طراحی

1. ** Separation of Concerns:** توابع خالص از منطق دیتابیس جدا هستند
   - `groupBySkill()` → فقط پردازش داده
   - `classifyTrend()` → فقط ریاضیات
   - Endpoint methods → فقط کوئری و ترکیب

2. **رگرسیون خطی برای تشخیص روند:** استفاده از Least Squares برای تشخیص عینی روند یادگیری

3. **پشتیبانی چند نقشی:** هر endpoint دسترسی‌های مختلفی برای نقش‌های مختلف دارد

4. **انعطاف‌پذیری:** پارامتر اختیاری `courseId` در اکثر متدها امکان فیلتر بر اساس دوره خاص را فراهم می‌کند

5. **استفاده مشترک:** متد `groupBySkill()` در چندین endpoint و حتی در سرویس Recommendations استفاده می‌شود

### ❌ محدودیت‌ها و بهبودهای احتمالی

1. **آستانه ثابت trend:** آستانه `±2` برای تشخیص روند ممکن است برای همه سناریوها مناسب نباشد

2. **عدم در نظر گرفتن وزن سوالات:** همه سوالات آزمون وزن یکسانی دارند

3. **عدم استفاده از Median:** میانگین حساس به نمرات خیلی بالا/پایین است

4. **پردازش سنگین Endpoint 5:** در کلاس‌های بزرگ ممکن است کند شود

### 💡 پیشنهادات برای ارتقاء

1. افزودن **_analyst_** برای تشخیص الگوهای پیچیده‌تر
2. استفاده از **Percentile** به جای فقط درصد ساده
3. افزودن **هشدار خودکار** برای دانشجویان با روند نزولی
4. استفاده از **Redis Cache** برای کوئری‌های پرتکرار
5. افزودن **Audit Log** برای پیگیری تغییرات
