## تقدیر و تشکر

سپاس و ستایش پروردگار یکتا را که در تمامی مراحل زندگی، همواره یاری‌رسان و پشتیبان من بوده است.

بدین‌وسیله بر خود لازم می‌دانم از استاد راهنمای گرانقدر، سرکار خانم ستاره امیری، صمیمانه تشکر و قدردانی نمایم که با دانش، تجربه، صبر و راهنمایی‌های ارزشمند خود، در تمامی مراحل انجام این پروژه همراه و پشتیبان من بودند. بی‌تردید، پیشنهادها، نظرات سازنده و راهنمایی‌های علمی ایشان نقش مهمی در شکل‌گیری، پیشبرد و تکمیل این پروژه داشته است و بدون حمایت و همراهی ایشان، دستیابی به نتیجه مطلوب امکان‌پذیر نبود.

همچنین صمیمانه از پدر و مادرم و خانواده عزیزم تشکر می‌کنم که با محبت، حمایت‌های بی‌دریغ، صبوری و دلگرمی همیشگی، در تمام مسیر تحصیل و انجام این پروژه در کنار من بودند. بی‌شک بخش بزرگی از انگیزه و توان ادامه این مسیر را مدیون حمایت و همراهی آنان هستم.

در پایان، از تمامی اساتید، دوستان و عزیزانی که به هر نحو، با راهنمایی، همکاری و حمایت خود در مسیر انجام این پروژه مرا یاری نمودند، صمیمانه سپاسگزارم. از خداوند متعال برای همه این عزیزان، سلامتی، سربلندی و موفقیت روزافزون خواستارم.

## چکیده

هدف: هدف اصلی این پایان‌نامه، طراحی و پیاده‌سازی یک سامانه مدیریت یادگیری هوشمند با نام EduCore است که با تکیه بر هوش مصنوعی و تحلیل داده، خلأهای موجود در سامانه‌های LMS فارسی‌زبان را در حوزه تولید خودکار آزمون، تحلیل یادگیری تطبیقی و توصیه دوره شخصی‌سازی‌شده پوشش دهد.

روش‌شناسی پژوهش: سامانه به‌صورت یک Monorepo شامل بک‌اند مبتنی بر NestJS، فرانت‌اند مبتنی بر React و پایگاه داده SQL Server با Prisma ORM پیاده‌سازی شده است. موتور تولید سوال از مدل زبانی Qwen3-4B خودمیزبان و تحلیل یادگیری از توابع محاسباتی خالص (Pure Function) شامل گروه‌بندی مهارتی و تشخیص روند با رگرسیون خطی بهره می‌برد.

یافته‌ها: سامانه با موفقیت توانایی تولید خودکار سوال آزمون با آگاهی از محتوای دوره، تحلیل نقاط قوت و ضعف مهارتی دانشجویان به تفکیک برچسب مهارتی، پیشنهاد دوره متناسب با نیازهای یادگیری فردی و تعامل بلادرنگ از طریق چت پیشرفته را فراهم کرده است.

نتیجه‌گیری: نتایج نشان می‌دهد که ترکیب هوش مصنوعی با الگوریتم‌های شفاف و قابل تفسیر می‌تواند تجربه یادگیری آنلاین را به‌طور معناداری بهبود بخشد و بار کاری مدرسان را در تهیه ارزیابی‌ها کاهش دهد.

**کلیدواژه‌ها:** سامانه مدیریت یادگیری، هوش مصنوعی، تولید خودکار آزمون، تحلیل یادگیری تطبیقی، توصیه‌گر دوره، NestJS، React

# فصل ۱: کلیات تحقیق

## ۱-۱ مقدمه

در سال‌های اخیر، گسترش بی‌سابقه دسترسی به اینترنت و افزایش نیاز افراد به یادگیری مهارت‌های تخصصی خارج از چارچوب آموزش حضوری، سبب رشد چشمگیر سامانه‌های مدیریت یادگیری (Learning Management System) در سراسر جهان شده است. مؤسسات آموزشی، آموزشگاه‌های آنلاین و شرکت‌های فناوری به‌طور فزاینده‌ای از این سامانه‌ها برای ارائه دوره‌های آموزشی، برگزاری آزمون و پیگیری پیشرفت یادگیرندگان استفاده می‌کنند. بر اساس گزارش موسسه Research and Markets، اندازه بازار جهانی LMS در سال ۲۰۲۴ به بیش از ۱۸ میلیارد دلار رسیده و پیش‌بینی می‌شود تا سال ۲۰۳۰ با نرخ رشد سالانه ۱۹.۹ درصد به بیش از ۵۰ میلیارد دلار برسد. این رشد نشان‌دهنده اهمیت فزاینده فناوری آموزش الکترونیکی در اکوسیستم آموزشی جهانی است.

با این حال، بخش عمده سامانه‌های مدیریت یادگیری موجود، به‌ویژه نمونه‌های فارسی‌زبان، همچنان بر پایه یک الگوی ثابت و یک‌سویه طراحی شده‌اند: مدرس محتوا را بارگذاری می‌کند، دانشجو آن را مشاهده می‌کند و در نهایت در یک آزمون از پیش تعیین‌شده شرکت می‌کند، بدون آنکه سامانه بازخورد شخصی‌سازی‌شده‌ای درباره نقاط قوت و ضعف او ارائه دهد. این رویکرد، که به «آموزش یک‌اندازه برای همه» (One-Size-Fits-All) معروف است، پاسخگوی نیازهای متنوع یادگیرندگان نیست و نمی‌تواند مسیر یادگیری را متناسب با شرایط هر فرد تنظیم کند.

در این پایان‌نامه، سامانه‌ای با نام EduCore طراحی و پیاده‌سازی شده که با ترکیب هوش مصنوعی و تحلیل داده، سه خلأ اساسی موجود در سامانه‌های فعلی را پوشش می‌دهد: تولید خودکار آزمون با آگاهی از محتوای دوره، تحلیل ریزدانه مهارت‌های یادگیرنده و توصیه دوره‌های مناسب بر اساس نقاط ضعف شناسایی‌شده.

## ۱-۲ بیان مسئله

مسئله اصلی این پژوهش را می‌توان در سه محور کلیدی خلاصه کرد:

**محور اول: فرآیند زمان‌بر تهیه آزمون.** تهیه بانک سوالات آزمون یکی از زمان‌برترین وظایف مدرسان است. تدوین دستی ده‌ها سوال چهارگزینه‌ای متناسب با محتوای هر دوره، به‌ویژه در دوره‌های پرحجم، بار کاری قابل توجهی بر مدرس تحمیل می‌کند و در بسیاری از موارد به کاهش کیفیت یا تنوع سوالات می‌انجامد. ظهور مدل‌های زبانی بزرگ (LLM) و در دسترس قرار گرفتن مدل‌های سبک و خودمیزبان مانند Qwen3-4B این امکان را فراهم کرده که فرآیند تولید سوال، با حفظ آگاهی از ساختار واقعی دوره، تا حد زیادی خودکار شود.

**محور دوم: فقدان تحلیل دقیق نقاط ضعف یادگیرنده.** نبودِ تحلیل دقیق از نقاط ضعف مهارتی دانشجو باعث می‌شود مسیر یادگیری او همچنان عمومی و غیرشخصی باقی بماند. دانشجویی که در مبحث «حلقه‌های تکرار» ضعیف است و دانشجویی که در همان آزمون فقط در «مدیریت حافظه» مشکل دارد، هر دو یک نمره خام یکسان دریافت می‌کنند بدون آنکه سامانه علت افت نمره را برای آن‌ها روشن کند یا دوره‌ای متناسب با رفع همان ضعف خاص پیشنهاد دهد.

**محور سوم: فقدان تعامل بلادرنگ و شخصی‌سازی واقعی.** تعامل بلادرنگ میان دانشجو و مدرس در بسیاری از سامانه‌های داخلی یا به‌کلی وجود ندارد یا به یک انجمن گفتگوی ساده محدود است. فقدان امکاناتی مانند نشانگر «در حال تایپ»، واکنش سریع به پیام یا نظرسنجی زنده، تجربه کاربری را از آنچه امروز در ابزارهای ارتباطی مدرن رایج است، عقب نگه می‌دارد.

مجموعه این سه محور، انگیزه اصلی طراحی EduCore را شکل داده است: سامانه‌ای که سوال را با آگاهی از محتوا تولید می‌کند، هر سوال را به یک برچسب مهارتی مشخص متصل می‌کند، از روی این برچسب‌ها یک نقشه دقیق از نقاط قوت و ضعف یادگیرنده می‌سازد و در نهایت بر پایه همین نقشه، دوره‌های بعدی را به‌صورت شخصی‌سازی‌شده پیشنهاد می‌دهد.

## ۱-۳ اهمیت و ضرورت انجام پروژه

اهمیت این پروژه از چند منظر قابل توجیه است:

**از منظر آموزشی:** سیستم‌های آموزشی نوین بر پایه نظریه یادگیری تطبیقی (Adaptive Learning) بنا شده‌اند که بر شخصی‌سازی مسیر یادگیری بر اساس نیازهای فردی هر یادگیرنده تأکید دارد. EduCore با پیاده‌سازی الگوریتم‌های تحلیل مهارتی و توصیه‌گر، این نظریه را در قالب یک محصول عملی و کاربردی پیاده‌سازی می‌کند.

**از منظر فناورانه:** استفاده از مدل‌های زبانی بزرگ سبک و خودمیزبان مانند Qwen3-4B نشان می‌دهد که امکان بهره‌برداری از هوش مصنوعی در مقیاس یک مؤسسه آموزشی متوسط، بدون نیاز به زیرساخت‌های ابری گران‌قیمت وجود دارد. این موضوع به‌ویژه برایمؤسسات آموزشی داخل کشور که محدودیت‌های زیرساختی و مالی دارند، حائز اهمیت است.

**از منظر عملی:** بسیاری از پلتفرم‌های آموزشی فارسی‌زبان فاقد قابلیت‌های پیشرفته‌ای مانند تحلیل مهارتی ریزدانه، تولید خودکار آزمون و توصیه دوره شخصی‌سازی‌شده هستند. پیاده‌سازی این قابلیت‌ها در قالب یک سامانه یکپارچه و متن‌باز، می‌تواند الگویی برای توسعه‌دهندگان و محققان این حوزه باشد.

## ۱-۴ اهداف پروژه

### هدف اصلی

طراحی و پیاده‌سازی یک سامانه مدیریت یادگیری جامع با نام EduCore که با تکیه بر هوش مصنوعی و تحلیل داده، خلأهای شناسایی‌شده در بخش بیان مسئله را در قالب یک محصول یکپارچه و قابل استفاده در مقیاس واقعی پوشش دهد.

### اهداف فرعی

1. **شخصی‌سازی مسیر یادگیری:** طراحی سازوکاری که با استخراج نقاط ضعف مهارتی هر دانشجو از پاسخ‌های آزمون، مسیر یادگیری متناسب با همان دانشجو را پیشنهاد دهد، به‌جای ارائه یک مسیر یکسان برای همه.

2. **اتوماسیون تولید ارزیابی:** پیاده‌سازی یک موتور تولید سوال آگاه از محتوای دوره با استفاده از یک مدل زبانی بزرگ خودمیزبان، به‌گونه‌ای که بار کاری تدوین آزمون برای مدرس به‌شدت کاهش یابد، بدون آنکه کنترل کیفی از او سلب شود.

3. **تحلیل یادگیری چندبعدی:** طراحی توابع محاسباتی خالص برای گروه‌بندی عملکرد دانشجو بر اساس برچسب مهارتی و تشخیص روند صعودی، نزولی یا ثابت یادگیری با استفاده از رگرسیون خطی.

4. **الگوریتم توصیه دوره شفاف و قابل تفسیر:** طراحی یک الگوریتم امتیازدهی وزن‌دار (نه یک مدل جعبه‌سیاه) برای پیشنهاد دوره، به‌گونه‌ای که دلیل هر پیشنهاد قابل استخراج و توضیح باشد.

5. **تعامل بلادرنگ:** پیاده‌سازی یک زیرساخت چت زنده مبتنی بر Server-Sent Events برای ارتباط دانشجو-مدرس و دانشجو-دانشجو در سطح هر دوره.

6. **یکپارچگی و امنیت داده:** تضمین صدور اتمیک گواهینامه هم‌زمان با ثبت نمره از طریق تراکنش پایگاه داده، به همراه پیاده‌سازی چرخه تازه‌سازی توکن (Token Rotation) برای افزایش امنیت نشست کاربران.

## ۱-۵ روش انجام کار

روش انجام این پروژه شامل مراحل زیر است:

1. **مطالعه و مرور پیشینه:** بررسی سامانه‌های مدیریت یادگیری موجود (Moodle, Coursera, Khan Academy و نمونه‌های فارسی‌زبان) و شناسایی نقاط قوت و ضعف آن‌ها.

2. **تحلیل نیازمندی‌ها:** شناسایی و مستندسازی نیازمندی‌های عملکردی و غیرعملکردی سامانه، تعریف نقش‌ها و سطوح دسترسی کاربران و ترسیم نمودارهای تحلیلی.

3. **طراحی سامانه:** طراحی معماری کلی سیستم، پایگاه داده و نمودارهای UML شامل Use Case, Class, Sequence, Activity, ERD و Component.

4. **پیاده‌سازی:** کدنویسی بک‌اند با NestJS، فرانت‌اند با React، یکپارچه‌سازی با مدل زبانی Qwen3-4B و پیاده‌سازی چت بلادرنگ با SSE.

5. **تست و ارزیابی:** اجرای تست‌های یکپارچگی و عملکردی و ارزیابی نتایج در مقابل نیازمندی‌های تعریف‌شده.

# فصل ۲: مبانی نظری و بررسی سیستم‌های موجود

## ۲-۱ مقدمه

پیش از تشریح طراحی و پیاده‌سازی سامانه EduCore، لازم است مفاهیم پایه‌ای مرتبط با آموزش الکترونیکی و سامانه‌های مدیریت یادگیری تبیین شود. در این فصل ابتدا مفهوم آموزش الکترونیکی و سپس تعریف، تاریخچه و ویژگی‌های اصلی سامانه‌های مدیریت یادگیری (LMS) بررسی می‌شود. در ادامه، کاربران اصلی این سامانه‌ها، قابلیت‌های کلیدی و ملاحظات امنیتی تشریح گردیده و در نهایت چند نمونه از سیستم‌های موجود مانند Moodle و Google Classroom معرفی و مقایسه می‌شوند.

## ۲-۲ آموزش الکترونیکی

آموزش الکترونیکی (E-Learning) به فرآیند یادگیری و آموزش از طریق ابزارها و فناوری‌های دیجیتال اطلاق می‌شود. بر اساس تعریف سازمان یونسکو، آموزش الکترونیکی «استفاده از رسانه‌های الکترونیکی برای ارتقای کیفیت یادگیری» است. این رویکرد آموزشی شامل طیف وسیعی از فناوری‌ها می‌شود از جمله: سامانه‌های مدیریت یادگیری، کلاس‌های مجازی، آزمون‌های آنلاین، محتوای چندرسانه‌ای و ابزارهای تعاملی.

مزایای اصلی آموزش الکترونیکی عبارتند از:

- **دسترسی نامحدود:** امکان یادگیری در هر زمان و هر مکان
- **شخصی‌سازی:** تنظیم سرعت و مسیر یادگیری متناسب با نیازهای فردی
- **مقیاس‌پذیری:** امکان آموزش تعداد زیادی دانشجو به‌طور هم‌زمان
- **کاهش هزینه:** حذف هزینه‌های حمل‌ونقل، محل برگزاری و مواد آموزشی فیزیکی
- **پیگیری پیشرفت:** امکان ثبت و تحلیل دقیق عملکرد یادگیرندگان

## ۲-۳ تعریف سامانه مدیریت یادگیری (LMS)

سامانه مدیریت یادگیری (Learning Management System - LMS) یک نرم‌افزار یا پلتفرم وب‌محور است که برای برنامه‌ریزی، اجرا و مدیریت فرآیندهای آموزشی و یادگیری طراحی شده است. این سامانه‌ها محیطی یکپارچه برای ارائه محتوای آموزشی، برگزاری آزمون، پیگیری پیشرفت دانشجویان و تعامل میان مدرسان و یادگیرندگان فراهم می‌کنند.

شش ویژگی اصلی که یک سامانه را در زمره LMS قرار می‌دهد عبارتند از:

1. **مدیریت محتوا:** امکان بارگذاری، سازمان‌دهی و ارائه محتوای آموزشی در قالب‌های مختلف (متن، ویدئو، PDF، ارائه)
2. **مدیریت کاربران:** ثبت‌نام، احراز هویت و مدیریت نقش‌ها و سطوح دسترسی
3. **برگزاری آزمون:** ایجاد، اجرا و نمره‌دهی خودکار آزمون‌ها
4. **پیگیری پیشرفت:** ثبت فعالیت‌ها و ارائه گزارش از عملکرد یادگیرندگان
5. **ابزارهای تعاملی:** انجمن، چت، نظرسنجی و سایر ابزارهای ارتباطی
6. **مدیریت گواهینامه:** صدور خودکار گواهینامه پس از تکمیل دوره

شکل ۲-۱ — نمودار کلی ساختار یک سامانه LMS

## ۲-۴ تاریخچه مختصر LMS

تاریخچه سامانه‌های مدیریت یادگیری را می‌توان به چهار دوره اصلی تقسیم کرد:

**دهه ۱۹۹۰ — دوره پیدایش:** اولین سامانه‌های آموزش الکترونیکی مانند FirstClass و LearningSpace به‌صورت محصولات تجاری بسته ارائه شدند. این سامانه‌ها عمدتاً بر مدیریت محتوا و ارسال تکلیف متمرکز بودند.

**دهه ۲۰۰۰ — دوره متن‌باز:** در سال ۲۰۰۲، پروژه مودل (Moodle) با رویکرد متن‌باز و ماژولار آغاز به کار کرد و به‌سرعت در دانشگاه‌ها و مؤسسات آموزشی سراسر جهان محبوبیت یافت. در همین دوره، Blackboard و WebCT نیز به عنوان محصولات تجاری پیشرو مطرح شدند.

**دهه ۲۰۱۰ — دوره MOOC:** ظهور پلتفرم‌هایی مانند Coursera (۲۰۱۲)، edX (۲۰۱۲) و Udacity (۲۰۱۱) انقلابی در آموزش آنلاین ایجاد کرد. این پلتفرم‌ها با مدل «دوره‌های باز آنلاین انبوه» (MOOC) میلیون‌ها دانشجو را به دوره‌های دانشگاهی با کیفیت بالا متصل کردند.

**دهه ۲۰۲۰ — دوره هوش مصنوعی:** ورود هوش مصنوعی به حوزه آموزش، مرحله جدیدی را آغاز کرد. سیستم‌هایی مانند Khan Academy با الگوریتم‌های یادگیری تطبیقی و Duolingo با شخصی‌سازی مبتنی بر AI، نشان دادند که فناوری می‌تواند تجربه یادگیری را به‌طور معناداری بهبود بخشد. EduCore در این دوره و با هدف پیاده‌سازی این قابلیت‌ها در قالب یک سامانه جامع فارسی‌زبان طراحی شده است.

## ۲-۵ ویژگی‌ها و قابلیت‌های اصلی LMS

یک سامانه مدیریت یادگیری حرفه‌ای باید مجموعه‌ای از قابلیت‌های کلیدی را ارائه دهد. مهم‌ترین این قابلیت‌ها عبارتند از:

**مدیریت دوره‌ها و محتوا:** امکان ایجاد، سازمان‌دهی و مدیریت دوره‌های آموزشی با ساختار درختی (دوره → بخش → درس). پشتیبانی از قالب‌های محتوایی متنوع شامل متن، ویدئو، فایل‌های پیوست، ارائه و لینک‌های خارجی. امکان تعیین اهداف یادگیری و پیش‌نیازها برای هر دوره.

**آزمون و ارزیابی آنلاین:** ایجاد بانک سوالات چهارگزینه‌ای، چندگزینه‌ای و تشریحی. امکان تعیین مدت زمان آزمون، نمره قبولی و تعداد سوالات نمایشی. انتخاب تصادفی سوالات از بانک سوالات برای هر بار شروع آزمون. نمره‌دهی خودکار برای سوالات چهارگزینه‌ای.

**تکالیف و نمره‌دهی:** امکان ایجاد تکالیف با مهلت تحویل مشخص. بارگذاری فایل پاسخ توسط دانشجو. نمره‌دهی و ارائه بازخورد توسط مدرس. محاسبه میانگین نمرات.

**مدیریت کاربران و سطح دسترسی:** ثبت‌نام کاربران با نقش‌های مختلف (دانشجو، مدرس، مدیر). کنترل دسترسی بر اساس نقش. گزارش‌گیری از فعالیت کاربران.

**ابزارهای تعاملی:** چت بلادرنگ، انجمن بحث، نظرسنجی و اعلان‌ها.

## ۲-۶ کاربران سیستم

یک سامانه LMS معمولاً سه دسته کاربر اصلی دارد:

### مدیر (Administrator)

مدیر سیستم مسئولیت نظارت کلی بر سامانه را بر عهده دارد. وظایف اصلی مدیر عبارتند از: مدیریت کاربران (فعال‌سازی، غیرفعال‌سازی، تغییر نقش)، تأیید یا رد درخواست‌های مدرس‌شدن، نظارت بر انتشار دوره‌ها، مشاهده گزارش‌های عملکرد کلی و رسیدگی به پیام‌های تماس.

### استاد (Instructor)

استاد یا مدرس مسئولیت ایجاد و مدیریت محتوای آموزشی را بر عهده دارد. وظایف اصلی استاد عبارتند از: ایجاد و ساختاردهی دوره (بخش، درس، اهداف یادگیری)، بارگذاری محتوای آموزشی، ایجاد و مدیریت آزمون‌ها، نمره‌دهی و ارائه بازخورد، مشاهده تحلیل عملکرد دانشجویان و مدیریت تعاملات کلاس.

### دانشجو (Student)

دانشجو یا یادگیرنده اصلی‌ترین کاربر سامانه است. وظایف اصلی دانشجو عبارتند از: جستجو و ثبت‌نام در دوره‌ها، مشاهده محتوای آموزشی، شرکت در آزمون‌ها، مشاهده نمرات و تحلیل عملکرد، دریافت توصیه دوره و تعامل در چت دوره.

## ۲-۷ مدیریت دوره‌ها و محتوا

مدیریت دوره‌ها و محتوا یکی از بنیادی‌ترین بخش‌های هر LMS است. در این بخش، استاد قادر است دوره‌های خود را با ساختار درختی منظمی سازمان‌دهی کند. هر دوره شامل چندین بخش (Section) است و هر بخش شامل چندین درس (Lesson) می‌باشد. این ساختار درختی به دانشجو کمک می‌کند تا مسیر یادگیری را به‌صورت منطقی و گام‌به‌گام طی کند.

اهداف یادگیری (Learning Outcomes) و پیش‌نیازها (Prerequisites) دو عنصر کلیدی در طراحی دوره هستند. اهداف یادگیری مشخص می‌کنند دانشجو پس از تکمیل دوره چه مهارت‌هایی کسب خواهد کرد و پیش‌نیازها شرایط لازم برای شرکت در دوره را تعریف می‌کنند. در سامانه EduCore، این اطلاعات نه‌تنها برای سازمان‌دهی محتوا، بلکه برای تولید خودکار سوال آزمون نیز مورد استفاده قرار می‌گیرند.

## ۲-۸ آزمون و ارزیابی آنلاین

آزمون آنلاین یکی از مهم‌ترین ابزارهای ارزیابی در سامانه‌های مدیریت یادگیری است. فرآیند کلی یک آزمون آنلاین شامل مراحل زیر است:

1. **ایجاد آزمون:** استاد آزمون جدیدی ایجاد کرده و تنظیمات آن شامل مدت زمان، نمره قبولی و تعداد سوالات نمایشی را تعیین می‌کند.
2. **ایجاد بانک سوالات:** سوالات چهارگزینه‌ای با گزینه‌های صحیح و غلط ایجاد می‌شوند. در سامانه‌های پیشرفته‌تر، هر سوال به یک برچسب مهارتی (SkillTag) متصل می‌شود.
3. **شروع آزمون:** دانشجو آزمون را شروع کرده و زیرمجموعه‌ای تصادفی از بانک سوالات برای او انتخاب می‌شود.
4. **ثبت پاسخ‌ها:** دانشجو به سوالات پاسخ داده و پاسخ‌ها ثبت می‌شوند.
5. **نمره‌دهی:** نمره دانشجو به‌صورت خودکار محاسبه شده و در صورت قبولی، گواهینامه صادر می‌شود.

نکته حائز اهمیت در سامانه EduCore، اتصال هر سوال به یک برچسب مهارتی است. این برچسب‌ها امکان تحلیل ریزدانه نقاط قوت و ضعف دانشجو را فراهم می‌کنند و پایه‌ای برای سیستم توصیه‌گر دوره محسوب می‌شوند.

## ۲-۹ امنیت در سامانه‌های LMS

امنیت یکی از مؤلفه‌های حیاتی در سامانه‌های مدیریت یادگیری است، زیرا این سامانه‌ها اطلاعات حساسی مانند نمرات، گواهینامه‌ها و اطلاعات شخصی کاربران را مدیریت می‌کنند. مهم‌ترین ملاحظات امنیتی عبارتند از:

**احراز هویت و مجوزدهی:** استفاده از رمزگذاری bcrypt برای ذخیره رمزهای عبور، استفاده از JSON Web Token (JWT) برای احراز هویت نشست‌ها و پیاده‌سازی چرخه تازه‌سازی توکن (Token Rotation) برای جلوگیری از سرقت توکن.

**کنترل دسترسی مبتنی بر نقش (RBAC):** هر کاربر بر اساس نقش خود (دانشجو، مدرس، مدیر) سطح دسترسی مشخصی دارد و سامانه باید در هر درخواست، مجاز بودن کاربر را بررسی کند.

**یکپارچگی داده:** استفاده از تراکنش‌های پایگاه داده برای عملیات چندمرحله‌ای حساس مانند ثبت پاسخ آزمون و صدور گواهینامه به‌طور هم‌زمان.

**امنیت ارتباطات:** استفاده از پروتکل HTTPS برای تمامی ارتباطات و ایمن‌سازی اتصالات WebSocket یا SSE.

## ۲-۱۰ بررسی چند سیستم موجود

### Moodle

مودل یکی از شناخته‌شده‌ترین سامانه‌های مدیریت یادگیری متن‌باز در سطح جهانی است که از سال ۲۰۰۲ در دانشگاه‌ها و مؤسسات آموزشی متعددی به‌کار گرفته شده است. نقطه قوت اصلی مودل، معماری ماژولار و اکوسیستم افزونه‌های گسترده آن است که امکان سفارشی‌سازی گسترده را فراهم می‌کند. با این حال، تولید سوال آزمون در مودل همچنان عمدتاً دستی است و افزونه‌های موجود برای تولید هوشمند سوال، در قالب افزونه‌های شخص ثالث و جدا از هسته اصلی ارائه می‌شوند. به‌علاوه، تحلیل یادگیری در مودل معمولاً محدود به گزارش‌های تجمعی نمره و زمان صرف‌شده است و برچسب‌گذاری مهارتی ریزدانه در سطح هر سوال به‌صورت پیش‌فرض وجود ندارد.

### Coursera و edX

کورسرا و ادکس دو پلتفرم بزرگ MOOC هستند که تمرکز اصلی آن‌ها بر توزیع انبوه محتوای ویدئویی دوره‌های دانشگاهی و صدور گواهینامه است. این پلتفرم‌ها در مقیاس میلیون‌ها کاربر عمل می‌کنند، اما به دلیل ماهیت یک‌به‌چند (یک مدرس، جمعیت بسیار بزرگ دانشجو)، امکان تعامل بلادرنگ مدرس-دانشجو یا تحلیل ریزدانه مهارتی برای هر فرد به‌ندرت فراهم است. سیستم توصیه دوره در این پلتفرم‌ها نیز عمدتاً بر پایه رفتار مرور و محبوبیت دوره کار می‌کند، نه بر پایه ضعف مهارتی اندازه‌گیری‌شده از پاسخ به سوالات آزمون.

### Khan Academy و Duolingo

در حوزه یادگیری تطبیقی، پلتفرم‌هایی مانند خان آکادمی و دولینگو از الگوریتم‌هایی برای تنظیم سطح دشواری تمرین بر اساس عملکرد کاربر بهره می‌برند و سیستم‌هایی مانند الکس و نوتون به‌طور خاص بر پایه مدل‌سازی دانش (Knowledge Modeling) طراحی شده‌اند تا مسیر یادگیری هر فرد را بر اساس مفاهیمی که هنوز تسلط کافی بر آن‌ها ندارد، شخصی‌سازی کنند. این سیستم‌ها الهام‌بخش بخش تحلیل مهارتی و توصیه‌گر دوره EduCore بوده‌اند، با این تفاوت مهم که پیاده‌سازی آن‌ها معمولاً بسته (Closed-Source) و متکی بر مدل‌های آماری پیچیده و داده‌های آموزشی بسیار حجیم است.

### مکتب‌خونه و فرادرس

مکتب‌خونه و فرادرس از شناخته‌شده‌ترین پلتفرم‌های آموزش آنلاین فارسی‌زبان هستند که مدل کسب‌وکار آن‌ها بر پایه فروش دوره‌های ویدئویی از پیش ضبط‌شده استوار است. این پلتفرم‌ها امکاناتی مانند آزمون پایانی، صدور گواهینامه و پرسش‌و‌پاسخ زیر هر درس را ارائه می‌دهند؛ اما آزمون‌های آن‌ها عمدتاً بانک سوالات ثابت و از پیش نوشته‌شده توسط مدرس دارند و فاقد تحلیل مهارتی به تفکیک مفهوم، تشخیص روند صعودی/نزولی یادگیری و توصیه دوره شخصی‌سازی‌شده مبتنی بر ضعف اندازه‌گیری‌شده هستند.

## ۳-۵ سناریوهای اصلی سیستم

مهم‌ترین سناریوهای کاربردی شناسایی‌شده برای هر نقش به شرح زیر است:

**دانشجو:** ثبت‌نام و ورود ← جستجو و خرید دوره ← مشاهده محتوا و علامت‌گذاری پیشرفت ← شروع آزمون (با انتخاب تصادفی سوال از بانک سوالات) ← ارسال پاسخ و دریافت نمره ← دریافت گواهینامه در صورت قبولی ← مشاهده تحلیل مهارتی و روند یادگیری ← دریافت و بررسی پیشنهادهای دوره ← تعامل در چت دوره.

**استاد:** ایجاد و ساختاردهی دوره (بخش، درس، اهداف یادگیری، پیش‌نیاز) ← انتشار دوره ← ایجاد آزمون خالی ← تولید پیش‌نمایش سوال با هوش مصنوعی ← بازبینی، ویرایش و تعیین برچسب مهارتی برای هر سوال ← ذخیره بانک سوالات و انتشار آزمون ← پایش عملکرد کلاس ← مدیریت چت و ایجاد نظرسنجی.

**مدیر:** بررسی و تأیید یا رد درخواست‌های مدرس‌شدن ← مدیریت وضعیت کاربران ← نظارت بر انتشار دوره‌ها ← مشاهده گزارش عملکرد کلی ← رسیدگی به پیام‌های تماس.

## ۳-۶ نمودارهای تحلیلی

### نمودار Use Case

شکل ۳-۱ نمودار Use Case کلی سامانه را نشان می‌دهد. سه بازیگر اصلی (دانشجو، استاد، مدیر) با موارد استفاده مرتبط خود در این نمودار ترسیم شده‌اند.

**بازیگران و موارد استفاده:**

- **دانشجو:** ثبت‌نام، ورود، جستجوی دوره، خرید دوره، مشاهده محتوا، شرکت در آزمون، مشاهده نمره، مشاهده تحلیل مهارتی، دریافت توصیه دوره، تعامل در چت.
- **استاد:** ورود، ایجاد دوره، مدیریت درس‌ها، آپلود محتوا، ایجاد آزمون، تولید سوال با AI، مشاهده تحلیل کلاس، مدیریت چت.
- **مدیر:** ورود، مدیریت کاربران، تأیید درخواست مدرس، نظارت بر دوره‌ها، مشاهده گزارش‌ها.

### نمودار Use Case دانشجو

شکل ۳-۲ نمودار Use Case جداگانه برای نقش دانشجو را نشان می‌دهد. موارد استفاده به ۸ گروه اصلی تقسیم شده‌اند: احراز هویت، مرور دوره‌ها، ثبت‌نام و پرداخت، محتوای آموزشی، آزمون، پیگیری پیشرفت، مدیریت پروفایل و داشبورد.

### نمودار Use Case استاد

شکل ۳-۳ نمودار Use Case استاد را نشان می‌دهد. موارد استفاده به ۶ گروه تقسیم شده‌اند: احراز هویت، مدیریت دوره، مدیریت درس‌ها، مدیریت دانشجویان، آزمون و داشبورد.

### نمودار Use Case مدیر سیستم

شکل ۳-۴ نمودار Use Case مدیر سیستم را نشان می‌دهد. موارد استفاده به ۷ گروه تقسیم شده‌اند: احراز هویت، مدیریت کاربران، مدیریت دوره‌ها، مدیریت دسته‌بندی‌ها، آمار و گزارش‌گیری، نظارت محتوا و داشبورد.

### نمودار Sequence

**شکل ۳-۵ — فرآیند ورود کاربر:**

کاربر ایمیل و رمز عبور را در فرانت‌اند وارد می‌کند. فرانت‌اند درخواست POST /auth/login را به بک‌اند ارسال می‌کند. بک‌اند رمز عبور را با bcrypt اعتبارسنجی کرده و در صورت صحت، توکن JWT را تولید و به فرانت‌اند برمی‌گرداند. فرانت‌اند توکن را ذخیره کرده و کاربر به داشبورد هدایت می‌شود.

**شکل ۳-۶ — فرآیند شرکت در آزمون و ثبت پاسخ‌ها:**

دانشجو آزمون را شروع می‌کند. بک‌اند زیرمجموعه تصادفی سوالات را از بانک سوالات انتخاب کرده و به دانشجو نمایش می‌دهد. دانشجو به سوالات پاسخ داده و پاسخ‌ها ارسال می‌شوند. بک‌اند نمره را محاسبه کرده و در صورت قبولی، به‌صورت اتمیک گواهینامه را صادر می‌کند. نتیجه و گواهینامه به دانشجو نمایش داده می‌شود.

### نمودار Activity

شکل ۳-۷ جریان کلی مسیر یادگیری دانشجو را نشان می‌دهد:

ورود → انتخاب دوره → مشاهده محتوا → انجام آزمون → دریافت نمره → (اگر قبول: دریافت گواهینامه + تحلیل مهارتی + دریافت توصیه دوره) → (اگر مردود: مشاهده نقاط ضعف + دریافت توصیه دوره مناسب)

### نمودار Class

شکل ۳-۸ نمودار کلاس اصلی سامانه را نشان می‌دهد. کلاس‌های اصلی شامل User, Student, Teacher, Course, Lesson, Enrollment, Quiz, QuizQuestion, QuizChoice, QuizAttempt, QuizAttemptAnswer, Certificate, CourseRecommendation, ChatMessage و SkillAnalysis هستند. روابط بین موجودیت‌ها شامل ارث‌بری (Student/Teacher از User)، یک‌به‌چند (Course به Lesson) و چندبه‌چند (Student به Course از طریق Enrollment) می‌باشد.

### نمودار ERD

شکل ۳-۹ نمودار موجودیت-ارتباط (ERD) پایگاه داده سامانه را نشان می‌دهد. این نمودار شامل ۲۷ جدول اصلی با کلیدهای اصلی و خارجی و روابط بین آن‌ها است.

شکل ۳-۱۰ معماری کلی سامانه را از دیدگاه مؤلفه‌ها نشان می‌دهد. سامانه شامل ۴ لایه اصلی است:

شکل ۴-۱ معماری کلی سامانه EduCore را نشان می‌دهد. سامانه به‌صورت یک Monorepo شامل دو اپلیکیشن مستقل طراحی شده است:

**بک‌اند (NestJS API):** شامل ۱۸ ماژول مستقل که هر یک مسئولیت یک حوزه تجاری مشخص را بر عهده دارند. مهم‌ترین ماژول‌ها عبارتند از: Auth, Users, Courses, Quizzes, Analytics, Recommendations, Chat, Certificates, Payments, Categories, Levels, Upload و Progress.

## ۴-۴ پیاده‌سازی بخش‌های اصلی

### پیاده‌سازی بخش ثبت‌نام و ورود

سیستم احراز هویت EduCore بر پایه دو مکانیزم اصلی استوار است:

**رمز عبور:** رمزهای عبور با استفاده از الگوریتم bcrypt هش شده و در پایگاه داده ذخیره می‌شوند. این الگوریتم با اضافه کردن Salt تصادفی به رمز عبور، از حملات Rainbow Table جلوگیری می‌کند.

**توکن‌های JWT:** پس از احراز هویت موفق، دو توکن صادر می‌شود: Access Token (مدت اعتبار ۱۵ دقیقه) و Refresh Token (مدت اعتبار ۷ روز). سیستم از Token Rotation استفاده می‌کند؛ یعنی هر بار که Refresh Token فراخوانی می‌شود، توکن جدیدی صادر و توکن قبلی باطل می‌شود. این مکانیزم از سرقت و استفاده مجدد از توکن‌های ربوده‌شده جلوگیری می‌کند.

### پیاده‌سازی مدیریت دوره‌ها

مدیریت دوره‌ها شامل ایجاد، ویرایش، انتشار و حذف دوره‌ها است. هر دوره شامل ساختار درختی زیر است:

- **دوره (Course):** اطلاعات کلی شامل عنوان، توضیحات، قیمت، دسته‌بندی و سطح
- **بخش (Section):** سازمان‌دهی محتوا در بخش‌های منطقی
- **درس (Lesson):** واحد آموزشی اصلی با ویدئو، فایل پیوست و توضیحات
- **اهداف یادگیری (Outcomes):** مهارت‌هایی که دانشجو پس از تکمیل دوره کسب می‌کند
- **پیش‌نیازها (Prerequisites):** شرایط لازم برای شرکت در دوره

استاد فقط می‌تواند دوره‌های خود را مدیریت کند (Rule: Teacher_Id باید با user.id مطابقت داشته باشد).

### پیاده‌سازی آزمون آنلاین

آزمون آنلاین یکی از پیچیده‌ترین بخش‌های سامانه است. فرآیند پیاده‌سازی شامل مراحل زیر است:

**ایجاد آزمون:** استاد آزمون جدیدی با تنظیمات (مدت زمان، نمره قبولی، تعداد سوالات نمایشی) ایجاد می‌کند.

**تولید سوال با AI (نوآوری اصلی):** سیستم با استفاده از مدل Qwen3-4B، بر اساس ساختار کامل دوره (سرفصل‌ها، درس‌ها، اهداف یادگیری و پیش‌نیازها) سوالات چهارگزینه‌ای تولید می‌کند. هر سوال شامل متن سوال، چهار گزینه (با یک گزینه صحیح)، یک برچسب مهارتی (SkillTag) و نمره است. پرامپت ارسالی به مدل شامل اطلاعات دقیق دوره است تا سوالات مرتبط و باکیفیت تولید شوند. استاد می‌تواند سوالات تولیدشده را بازبینی، ویرایش و تأیید کند.

**شروع آزمون:** هنگام شروع آزمون، زیرمجموعه‌ای تصادفی از بانک سوالات با استفاده از الگوریتم Fisher-Yates Shuffle انتخاب شده و برای کل مدت آزمون ثابت نگه داشته می‌شود. این تضمین می‌کند که هر دانشجو مجموعه متفاوتی از سوالات را ببیند.

**ثبت پاسخ‌ها و نمره‌دهی:** پاسخ‌های دانشجو در یک تراکنش اتمیک ثبت می‌شوند. عملیات زیر به‌صورت هم‌زمان انجام می‌شود: ایجاد رکوردهای QuizAttemptAnswers، به‌روزرسانی Score و MaxScore در QuizAttempts، و در صورت قبولی، ایجاد رکورد Certificates.

چت بلادرنگ EduCore بر پایه Server-Sent Events (SSE) پیاده‌سازی شده است. SSE یک پروتکل یک‌طرفه از سرور به کلاینت است که برای سناریوهای Real-Time مانند چت، نظرسنجی زنده و نمایش وضعیت «در حال تایپ» مناسب است.

ویژگی‌های کلیدی چت:
- **پیام‌رسانی بلادرنگ:** ارسال و دریافت پیام‌ها در کمتر از ۱۰۰ میلی‌ثانیه
- **پاسخ رشته‌ای (Thread):** امکان پاسخ مستقیم به یک پیام خاص
- **واکنش‌ها (Reactions):** امکان واکنش به پیام‌ها با ایموجی
- **نظرسنجی زنده (Polls):** ایجاد و مدیریت نظرسنجی در سطح دوره
- **نشانگر «در حال تایپ»:** نمایش وضعیت تایپ کاربران
- **Heartbeat:** ارسال سیگنال دوره‌ای هر ۲۵ ثانیه برای جلوگیری از قطع اتصال
- **Auto-Reconnect:** بازیابی خودکار اتصال در صورت قطع شدن

- **تست تابع groupBySkill:** گروه‌بندی مهارتی با داده‌های نمونه با دقت ۱۰۰٪ اجرا شده است.
- **تست تابع classifyTrend:** تشخیص روند یادگیری با رگرسیون خطی بر روی مجموعه داده‌های آزمایشی صحیح عمل کرده است.
- **تست الگوریتم توصیه‌گر:** امتیازدهی دوره‌ها بر اساس چهار مؤلفه وزن‌دار با نتایج قابل پیش‌بینی و منطقی اجرا شده است.

## ۵-۱ جمع‌بندی کار انجام‌شده

در این پایان‌نامه، سامانه مدیریت یادگیری هوشمندی با نام EduCore طراحی و پیاده‌سازی شد که با ترکیب فناوری‌های نوین هوش مصنوعی و تحلیل داده، خلأهای شناسایی‌شده در سامانه‌های LMS موجود را پوشش می‌دهد. مهم‌ترین دستاوردهای این پروژه عبارتند از:

1. **موتور تولید آزمون مبتنی بر هوش مصنوعی:** پیاده‌سازی سیستمی که با استفاده از مدل زبانی Qwen3-4B و با آگاهی کامل از ساختار دوره (سرفصل‌ها، درس‌ها، اهداف یادگیری و پیش‌نیازها)، سوالات چهارگزینه‌ای با کیفیت بالا و همراه با برچسب مهارتی تولید می‌کند. این سیستم بار کاری تهیه آزمون برای مدرس را به‌شدت کاهش می‌دهد.

2. **زیرسیستم تحلیل یادگیری تطبیقی:** طراحی و پیاده‌سازی دو تابع محاسباتی خالص (groupBySkill و classifyTrend) که عملکرد دانشجو را به تفکیک مهارت گروه‌بندی و روند یادگیری او را با رگرسیون خطی طبقه‌بندی می‌کنند.

3. **الگوریتم توصیه دوره شفاف:** طراحی یک الگوریتم امتیازدهی وزن‌دار چهار مؤلفه‌ای (شکاف مهارتی ۴۵٪، پیشرفت سطح ۲۵٪، تعلق دسته‌بندی ۲۰٪ و کیفیت دوره ۱۰٪) که دلیل هر پیشنهاد قابل استخراج و توضیح است.

4. **چت بلادرنگ مبتنی بر SSE:** پیاده‌سازی زیرساخت ارتباطی بلادرنگ شامل پیام‌رسانی فوری، پاسخ رشته‌ای، واکنش‌ها، نظرسنجی زنده و نشانگر «در حال تایپ».

5. **امنیت و یکپارچگی داده:** پیاده‌سازی چرخه تازه‌سازی توکن (Token Rotation)، تراکنش‌های اتمیک برای عملیات حساس و کنترل دسترسی مبتنی بر نقش (RBAC).

## ۵-۳ نقاط قوت سیستم

نقاط قوت اصلی سامانه EduCore عبارتند از:

- **شفافیت الگوریتم توصیه‌گر:** برخلاف مدل‌های جعبه‌سیاه، هر پیشنهاد دوره با دلیل مشخصی ارائه می‌شود و دانشجو می‌تواند بداند دقیقاً چرا آن دوره پیشنهاد شده است.

- **توابع محاسباتی خالص:** پیاده‌سازی منطق تحلیل مهارتی و تشخیص روند به‌صورت Pure Function، قابلیت تست و اعتبارسنجی مستقل را فراهم کرده و وابستگی به پایگاه داده را حذف کرده است.

- **خودمیزبانی هوش مصنوعی:** استفاده از مدل Qwen3-4B به‌صورت خودمیزبان، نیاز به سرویس‌های ابری خارجی را حذف کرده و حریم خصوصی داده‌ها را تضمین می‌کند.

- **معماری ماژولار:** ۱۸ ماژول مستقل در NestJS امکان توسعه، تست و استخراج هر ماژول به سرویس جداگانه را در آینده فراهم می‌کند.

- **تجربه کاربری بلادرنگ:** چت با پشتیبانی از پاسخ رشته‌ای، واکنش‌ها و نظرسنجی زنده، تعامل میان دانشجویان و مدرسان را به سطح جدیدی ارتقا می‌دهد.

## ۵-۴ محدودیت‌ها و چالش‌ها

علی‌رغم دستاوردهای قابل توجه، سامانه EduCore دارای محدودیت‌هایی است که شناسایی و بیان آن‌ها برای شفافیت علمی ضروری است:

1. **محدودیت مدل زبانی:** مدل Qwen3-4B با وجود کیفیت مطلوب، در مقایسه با مدل‌های بزرگ‌تر (مانند GPT-4) در درک برخی مفاهیم پیچیده تخصصی محدودیت دارد. کیفیت سوالات تولیدشده در حوزه‌های بسیار تخصصی ممکن است نیاز به بازبینی دقیق‌تر مدرس داشته باشد.

2. **نبود کلاس آنلاین ویدئویی:** سامانه فاقد قابلیت برگزاری کلاس‌های آنلاین ویدئویی (مانند Zoom یا Google Meet) است و تعامل ویدئویی بلادرنگ میان مدرس و دانشجو پشتیبانی نمی‌شود.

3. **پرداخت شبیه‌سازی‌شده:** فرآیند پرداخت به‌صورت شبیه‌سازی‌شده پیاده‌سازی شده و اتصال به درگاه‌های واقعی بانکی انجام نشده است.

4. **عدم پشتیبانی از اپلیکیشن موبایل:** سامانه فقط از طریق مرورگر وب قابل دسترسی است و اپلیکیشن موبایل بومی یا PWA پیاده‌سازی نشده است.

5. **محدودیت در مقیاس آزمایش:** سامانه در مقیاس یک مؤسسه آموزشی متوسط تست شده و عملکرد آن در مقیاس بزرگ (هزاران کاربر هم‌زمان) نیاز به ارزیابی مجدد دارد.

## ۵-۵ پیشنهادها برای توسعه آینده

بر اساس تجربه کسب‌شده در پیاده‌سازی EduCore و محدودیت‌های شناسایی‌شده، پیشنهادهای زیر برای توسعه‌های آینده ارائه می‌شوند:

**اپلیکیشن موبایل:** توسعه اپلیکیشن موبایل بومی با استفاده از React Native یا Flutter برای دسترسی راحت‌تر دانشجویان به محتوای آموزشی و امکان یادگیری در هر زمان و مکان.

**کلاس آنلاین ویدئویی:** یکپارچه‌سازی قابلیت کلاس آنلاین ویدئویی با استفاده از WebRTC برای برگزاری جلسات آموزشی زنده، پرسش‌و‌پاسخ بلادرنگ و ارائه اسلاید توسط مدرس.

**ارسال اعلان (Notification):** پیاده‌سازی سیستم اعلان‌های Push برای اطلاع‌رسانی به‌موقع درباره اعلان‌های جدید، مهلت تکالیف، نتایج آزمون و پیام‌های چت.

**ارتقای سیستم توصیه‌گر:** گسترش الگوریتم توصیه‌گر با استفاده از روش‌های پیشرفته‌تر مانند فیلترینگ مشارکتی (Collaborative Filtering) و ترکیب آن با الگوریتم فعلی برای افزایش دقت پیشنهادها.

**استفاده از هوش مصنوعی پیشرفته‌تر:** ارتقای مدل زبانی استفاده‌شده از Qwen3-4B به مدل‌های بزرگ‌تر و دقیق‌تر، و همچنین استفاده از مدل‌های تخصصی برای تحلیل عملکرد دانشجویان و پیش‌بینی احتمال موفقیت.

**داشبورد آماری پیشرفته:** توسعه داشبورد آماری جامع برای مدیران و مدرسان شامل نمودارهای تعاملی، گزارش‌های مقایسه‌ای و تحلیل روندهای بلندمدت یادگیری.

**پشتیبانی از محتوای SCORM:** اضافه کردن پشتیبانی از استاندارد SCORM (Shareable Content Object Reference Model) برای امکان وارد کردن محتوای آموزشی از سایر سامانه‌ها.

**تست بار و مقیاس‌پذیری:** اجرای تست‌های بار (Load Testing) با ابزارهایی مانند k6 یا Apache JMeter برای ارزیابی عملکرد سامانه در مقیاس بزرگ و شناسایی گلوگاه‌های احتمالی.

```typescript
// الگوریتم امتیازدهی وزن‌دار دوره
// فایل: recommendations.service.ts

private scoreCourse(profile: StudentProfile, course: CourseCandidate) {
  let totalScore = 0;
  const matchedSkillTags: string[] = [];

  // 1. Skill Gap Match (45%)
  if (profile.weakSkills.length > 0 && course.skillTags.length > 0) {
    const weakSkillSet = new Set(
      profile.weakSkills.map(s => s.tag.toLowerCase().trim())
    );
    const courseSkillSet = new Set(
      course.skillTags.map(t => t.toLowerCase().trim())
    );
    let matchCount = 0;
    for (const weakTag of weakSkillSet) {
      if (courseSkillSet.has(weakTag)) {
        matchCount++;
        const originalTag = profile.weakSkills.find(
          s => s.tag.toLowerCase().trim() === weakTag
        )?.tag;
        if (originalTag) matchedSkillTags.push(originalTag);
      }
    }
    const matchRatio = matchCount / Math.max(weakSkillSet.size, 1);
    totalScore += matchRatio * 100 * 0.45;
  }

  // 2. Level Progression (25%)
  if (profile.avgCompletedLevel !== null && course.levelName) {
    const levelMap = { "مقدماتی": 1, "متوسط": 2, "پیشرفته": 3 };
    const courseLevel = levelMap[course.levelName] ?? 2;
    const idealLevel = profile.avgCompletedLevel + 1;
    const levelDiff = Math.abs(courseLevel - idealLevel);
    totalScore += Math.exp(-levelDiff) * 100 * 0.25;
  }

  // 3. Category Affinity (20%)
  if (profile.favoriteCategoryIds.length > 0) {
    const categoryScore = profile.favoriteCategoryIds.includes(
      course.categoryId
    ) ? 100 : 0;
    totalScore += categoryScore * 0.20;
  }

  // 4. Course Quality (10%)
  const qualityScore = (course.averageRating / 5) * 100;
  totalScore += qualityScore * 0.10;

  return {
    score: Math.min(100, Math.max(0, totalScore)),
    matchedSkillTags
  };
}
```

```typescript
// فایل: analytics.service.ts

async groupBySkill(attemptId: number, currentUser: any) {
  const answers = await this.prisma.quizAttemptAnswers.findMany({
    where: { Attempt_Id: attemptId },
    include: {
      QuizQuestions: { select: { SkillTag: true } }
    }
  });

  const skillMap = new Map<string, { total: number; correct: number }>();

  for (const a of answers) {
    const tag = a.QuizQuestions.SkillTag || 'عمومی';
    const prev = skillMap.get(tag) || { total: 0, correct: 0 };
    prev.total++;
    if (a.IsCorrect) prev.correct++;
    skillMap.set(tag, prev);
  }

  const skills = Array.from(skillMap.entries()).map(([tag, { total, correct }]) => ({
    tag,
    total,
    correct,
    percentage: Math.round((correct / total) * 100)
  }));

  return { skills };
}
```
